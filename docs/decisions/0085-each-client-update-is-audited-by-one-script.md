# 0085. Each client update is audited by one script

- Date: 2026-11-27
- Status: accepted
- Scope: all modules
- Kind: process

## Context

Each Forever client update changes Blizzard's UI source under the kit and every module: functions gain restrictions or arguments, deprecated shims come and go, files our hooks and citations name move. Nothing read the update the same way twice. The deprecated list, `tests/deprecated.lua`, was taken by hand and missed `UnitAura` (a shim in `Blizzard_Deprecated/Classic/Deprecated_1_15_8.lua`; only an event named `UnitAura` is in the API docs).

## Decision

Audit every client update, and every move of Gethe/wow-ui-source's `forever` branch, with `tools/client-audit.sh <old-ref> <new-ref>`, which writes one Markdown report:

1. the AddOns changed between the two commits and the client version of each;
2. the API diff of `Blizzard_APIDocumentationGenerated`: functions, events and tables added, removed or changed, with arguments, returns and flags (`HasRestrictions`, `SecretArguments` and the rest);
3. `tests/deprecated.lua` regenerated by `tools/deprecated.lua` at the new commit, and with `--strings` `tests/globalstrings.lua` by `tools/global-strings.lua`, each against ours;
4. our exposure across the kit and every module outside `Libs/`: calls into changed or removed API, each `hooksecurefunc` target with whether its Blizzard file changed, and each `file:line` citation of a changed Blizzard file, mapped to its line at the new commit;
5. the client-notes lines that name a build or a measurement, to check again in game.

The script only collects; the `client-audit` skill (`.claude/skills/client-audit/SKILL.md`) judges the report. The last audited commit is one line in `docs/client-notes.md`, "Audited source", and the script starts from it when no old ref is given.

## Reasons

- Scripts collect, judgment interprets: the same facts every time, read against the same docs.
- The API docs are what the client loads; running them against a stand-in for `APIDocumentation:AddDocumentationTable` reads them exactly, with no parsing of Lua by pattern.
- A generator states its rule in the list it writes, so the list is regenerated, never edited.
- A citation mapped through the diff tells which line numbers to fix without opening every file.

## Rejected

- Reading Blizzard's commit diff by hand per update: thousands of lines, read differently each time.
- A separate file for the last audited ref: one more file for one line the client notes already hold beside the build they describe.
- Fetching Ketho's global strings on every run: needs the network; it stays behind `--strings`.

## Versions

- Kit `tools/client-audit.sh`, `tools/client-audit.lua`, `tools/api-docs.lua`, `tools/deprecated.lua`, `tools/global-strings.lua` (takes a commit and an output path; one output on PUC Lua and LuaJIT), `tests/deprecated.lua` (regenerated, adds `UnitAura`), `scripts/check`, `docs/client-notes.md`, `docs/standards.md`.
- Run on `9465cb2` (1.60.1.70291) to `d9c22e3` (1.60.1.71139) in about 3 s.

## Tests

- `lua tools/deprecated.lua <source>/Interface/AddOns "1.60.1 (71139)"` at `d9c22e3` gives the hand-taken list plus `UnitAura`.
- `lua tools/global-strings.lua` at the pinned commit gives `tests/globalstrings.lua` byte for byte on PUC Lua 5.1.
- Two runs on the same refs, one from a fresh clone, give the same report.

## Reopen if

- Blizzard stops publishing `Blizzard_APIDocumentationGenerated`, or Gethe's mirror stops tracking `forever`.
